## Fable rulings ws3 round 3 (fable:ws3:2)
**Rulings (architect, ws3 doubts). No shared schema/KPI change is needed; only CONTRACTS.md must be brought in line with the real WS3 API (flagged below).**

**1. observation_id as a turn counter: KEEP, keyword required.**
Correct analysis. A page fingerprint cannot separate "before the click" from "after a dead click" (`browser.fingerprint` = url/text/actions/scroll; identical on both sides of a dead click), so a retried `act` would pass the check and run the mutation twice, violating "never retry a mutation". A monotonic nonce consumed by `_step()` (incremented in `finally`, whatever happened) is the only thing that makes "once" provable; element/document identity is already checked separately by `HostPolicy.__call__` (document key + node/label/value), so the two mechanisms cover different failures (duplicate call vs changed page). The cost ("the host must act on the id from the latest act()/observation()") is exactly the discipline we want the host to have. No caller uses the 3-argument form (mcp_server.py is a stub, no service.py exists), so making it required now is free; do not add a default later.
CONTRACT CHANGE (CONTRACTS.md, WS3 block, documentation only): `act(self, operation, target=None, text=None, *, observation_id: int) -> {executed, stale, refused, page_changed, step_metrics, status, observation}`; `observation()` returns `{observation_id, url, title, page_type, text_excerpt, elements, controls, step, budget_left, guard_notes, status[, omitted_elements]}`; `start(..., optimal_pages=None)`; `finish(status: "done"|"blocked"|None) -> {run_id, status, verification, friction, steps, steps_path}`; `HostPolicy.offer(page, observation_id)` / `.set(operation, target, text, observation_id)`; `friction.metrics(steps, *, optimal_steps, optimal_pages, success, profile, unverified)`; `oracles.verify(..., steps=)` (cart oracles also return `page`). Add to the WS5 block: `journey_act(run_id, operation, target?, text?, observation_id)` with `observation_id` required; the journey-driver skill must say "always pass the observation_id of the latest act()/observation() result; a `stale: true` reply means read the returned observation and choose again; never resend".

**2. Cart oracle reads the final cart page in place, no reload: KEEP.**
A reload re-sends the request that produced the page; with a GET add-to-cart (`?add-to-cart=7`) that is a second mutation, and the plan's "osservata di nuovo" means re-audited, not re-navigated. The staleness scenario (cart changed by another tab since render) cannot happen in a journey: one tab in an isolated `new_context`, and `_close_new_tabs` closes anything the page opens. The fixture test reloading itself is the right stand-in (the test plays the earlier tab); say so in one line of the oracles docstring ("the journey's single isolated tab is the cart's only writer, so the page as shown is the current state"). Keep `cart_source: "final_page"` in checks.

**3. find_cart priority: KEEP as implemented.**
