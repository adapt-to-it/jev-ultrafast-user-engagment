## Fable rulings ws3 round 3
**Rulings (architect, ws3 doubts). No shared schema/KPI change is needed; only CONTRACTS.md must be brought in line with the real WS3 API (flagged below).**

**1. observation_id as a turn counter: KEEP, keyword required.**
Correct analysis. A page fingerprint cannot separate "before the click" from "after a dead click" (`browser.fingerprint` = url/text/actions/scroll; identical on both sides of a dead click), so a retried `act` would pass the check and run the mutation twice, violating "never retry a mutation". A monotonic nonce consumed by `_step()` (incremented in `finally`, whatever happened) is the only thing that makes "once" provable; element/document identity is already checked separately by `HostPolicy.__call__` (document key + node/label/value), so the two mechanisms cover different failures (duplicate call vs changed page). The cost ("the host must act on the id from the latest act()/observation()") is exactly the discipline we want the host to have. No caller uses the 3-argument form (mcp_server.py is a stub, no service.py exists), so making it required now is free; do not add a default later.
CONTRACT CHANGE (CONTRACTS.md, WS3 block, documentation only): `act(self, operation, target=None, text=None, *, observation_id: int) -> {executed, stale, refused, page_changed, step_metrics, status, observation}`; `observation()` returns `{observation_id, url, title, page_type, text_excerpt, elements, controls, step, budget_left, guard_notes, status[, omitted_elements]}`; `start(..., optimal_pages=None)`; `finish(status: "done"|"blocked"|None) -> {run_id, status, verification, friction, steps, steps_path}`; `HostPolicy.offer(page, observation_id)` / `.set(operation, target, text, observation_id)`; `friction.metrics(steps, *, optimal_steps, optimal_pages, success, profile, unverified)`; `oracles.verify(..., steps=)` (cart oracles also return `page`). Add to the WS5 block: `journey_act(run_id, operation, target?, text?, observation_id)` with `observation_id` required; the journey-driver skill must say "always pass the observation_id of the latest act()/observation() result; a `stale: true` reply means read the returned observation and choose again; never resend".

**2. Cart oracle reads the final cart page in place, no reload: KEEP.**
A reload re-sends the request that produced the page; with a GET add-to-cart (`?add-to-cart=7`) that is a second mutation, and the plan's "osservata di nuovo" means re-audited, not re-navigated. The staleness scenario (cart changed by another tab since render) cannot happen in a journey: one tab in an isolated `new_context`, and `_close_new_tabs` closes anything the page opens. The fixture test reloading itself is the right stand-in (the test plays the earlier tab); say so in one line of the oracles docstring ("the journey's single isolated tab is the cart's only writer, so the page as shown is the current state"). Keep `cart_source: "final_page"` in checks.

**3. find_cart priority: KEEP as implemented.**
Order = visited cart pages/URLs whose query is empty after cleaning (classified pages first, URL-pattern matches after, which the current list construction already guarantees) > final page's `nav.cart_link` > visited URLs that keep a query. Rationale accepted: a page the journey actually loaded and the classifier called a cart is verified evidence; the cart link is a lexicon match on an href. When the visited URL keeps a query, the canonical link is safer and goes first, which is what you did. The finding's wording was a hint, not a required order; the implemented order is strictly better. Keep `cart_source` so the report shows which path was taken.

**4. CART_ACTION_KEYS / CART_ACTION_SEGMENTS conservative set: KEEP, add Italian.**
Accepted: a false positive drops a key or skips a candidate (the oracle then reports `cart_found: false`, never a wrong verdict and never a mutation). One gap: the sets are English only while the lexicon is IT+EN; add query keys `aggiungi|rimuovi|elimina|svuota|aggiorna|quantita|qta|azione` and path segments `{aggiungi, rimuovi, elimina, svuota, aggiorna, modifica}`. Keep them in oracles.py (they are a safety list, not user-facing lexicon; lexicon.py is WS1's). Pin one test with `/carrello/aggiungi` and `?aggiungi=3`.

**5. Gate logs the blocked host choice as a stale step with the reason note: KEEP.**
Consistent with the contract "a stale decision executes nothing and consumes no step" (`flags.stale` keeps it out of `friction.executed`). The note is accurate: the stop was detected on the Agent's pre-decision re-observation, so the page did change after the host's observation. No change.

**6. Agent no-progress stop vs FAI.RAGE_EVENTS: lift the stop for policy "host" in journey.py; keep it for "typesafe"; anchors unchanged.**
Decision: in `_decide_and_act`, when `agent.state["status"] == "blocked"` after an action and `self.host is not None`, reset `agent.state["status"] = "ready"` (the same pattern already used after `GuardRefused`), insert a guard note at the front of `self._notes` for the next observation ("no progress: three actions in a row changed nothing; choose another element or BLOCKED") and `_warn` it once; the run stays `running` and the step budget bounds it. For `typesafe` keep the current behaviour (status blocked + warning): there the stop is the only brake on a paid model looping on a dead control and the model has no notes channel.
Why: the Agent's stop is a demo safeguard, not a measurement rule. In host mode it turns a friction signal into a goal failure caused by the harness: the host is the policy and must own DONE/BLOCKED exactly as it owns every other choice; three deliberate clicks on three fresh observations are three decisions, not a retried mutation, so "never retry" is untouched. With the stop lifted the count is a real count (separate runs on different nodes give 2, 3, ...), the published anchors `0->100, 1->50, 3->0` are reachable, and FAI.JOURNEY_SUCCESS (weight 3) is no longer contaminated. Making the anchor binary would instead require editing anchors.json and docs/engagement-kpi.md (WS4/WS6a files) and would score one rage event as 0 on a provisional, weakly evidenced KPI; rejected. Document the typesafe saturation in one sentence of the friction/journey docstrings (count truncated at the Agent stop; the run warning records it). Tests to add in test_engagement_journey.py: after three dead clicks in host mode the status is still `running`, the next observation carries the note, a fourth click on the same node keeps `FAI.RAGE_EVENTS == 1` (one run), and two runs on two dead nodes give 2; a typesafe counter-page run still ends `blocked` with the existing warning. agent.py and tests/test_agent.py stay untouched.
