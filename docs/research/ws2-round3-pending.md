## Fable rulings ws2 round 3 (fable:ws2:2)
# Architect rulings for ws2 doubts (phase C)

Evidence read: `crawler.py` (`Tab.consent` 431-488, `Tab.act`/`click` 356-410, `dismiss` 490-517, `product` 766-777, `add_to_cart` 802-829, `checkout`/`guest_path` 873-945), `checks.py` (`_cta_above_fold`, `_salience`, `_site_row`, `_account_rows`), `deception.py` (`_closes`, `overlay_pages`, `_reappears`, `GONE`, `stock_contradictions`), `scoring.py` (`_pooled`/`_aggregate`: the ruling-5 per-profile `any` rule is not implemented there, unassessed rows are simply ignored when a usable row exists), `audit.js` (`ctaSummary.enabled`, `best()` prefers enabled controls, `structured.availability/offers`, `guestOption`/`login_required`, variant groups), `snapshot.js` line 57 (disabled controls are never observed), fixtures (`shop.js` 237/262: the cart's "Continua come ospite" leads to `checkout.html?guest=1`, which removes the required "Crea una password"), the phase-B rulings (`scratchpad/rulings_all.txt` 209-264), CONTRACTS "Coordinator decisions", doc 3.5 rule d and 5.2.

## 1. Guest path in `Crawl.checkout` — ADOPT, as implemented

Keep `guest_path()`. The rule is "reach the checkout entry the way a first-time buyer would": on a cart with two exits ("Accedi e acquista" / "Acquista come ospite", the classic Magento/PrestaShop layout the fixture models), the guest control *is* the first-time buyer's checkout CTA, and the account page behind the generic CTA is not the step Baymard counts. The CTA-only path would make the binding evidence rule ("checkout entry reached -> only evidence") misreport FORCED_ACCOUNT on honest shops, which is worse than the residual risk of an unexpected guest link. The constraints already in place are the right ones and are not to be loosened: one observed control matched by the `guest` lexicon key; a link only when its observed href is a same-site checkout URL (`guard.is_checkout`), a no-href control always; CheckoutGuard first; `navigated` -> entry `via: "guest"`; `quiet` (toggle) -> the checkout CTA follows; `timeout` or `failed:*` -> `Stop` (never a click on a page in an unknown state). Two small additions: (a) a `quiet` guest click whose fresh audit shows a new interrupting overlay is handled by `click(..., clear=True)` already, fine; (b) record `probe["guest"]["href"]` (the observed href, or null) so the report can show where the guest control led.

**CONTRACT CHANGE** (CONTRACTS.md, WS2 crawler line and "Checkout evidence" decision): "optional checkout_entry (click observed checkout CTA)" becomes "checkout entry via the cart's guest control when `forms.guest_option` is true and an observed `guest` control leads to a same-site checkout URL (or has no href), else via the observed checkout CTA; `probes.checkout_entry.via` ∈ {guest, checkout_cta}; FAI.CHECKOUT_FIELDS and rule d are measured on the step so reached". Doc 5.2 `checkout_entry` row owed to WS6b.

## 2. Ruling 5 site rows, `not_requested` and unreadable pages count as missing — UPHOLD the literal reading

A stage not observed is not observed, whatever the cause: a False `any` with a stage the user excluded (`not_requested`) or a page that was reached but could not be read (`navigation_error`, `audit_unavailable`) is not conclusive. The report's scope is what explains it, and the coverage gate is the protection: `not_requested` must keep lowering coverage (it is *not* `not_applicable:*`), otherwise a `--stages home,plp` audit would publish an ERS with "Confidenza A" on a handful of KPIs. Keep `audit.py` `ACCEPTED = ("not_requested",)` for run status (a scoped run is complete, not partial). Owed to WS4: `report.REASONS["not_requested"] = "stadio non richiesto"` (and `navigation_error`, `audit_unavailable`) so these reach the report as Italian text.

## 3. Rule d with an unreadable checkout page — KEEP the drop, carry the reason in evidence

Ruling 5 stands: the checkout NA row is emitted only in the "neither" case. A cart guest row is conclusive by rule d, and with the current `scoring._aggregate` (usable rows only) keeping the NA row would change no score, so this is about honesty of the KPI table, not arithmetic. The unreadable page is not lost: its page-scope KPIs (FAI.CHECKOUT_FIELDS, FAI.AUTOCOMPLETE_ATTRS, CCL.FORM_LABELS, PERF.*) already emit NA rows with that page's own reason. One addition: when a checkout row was dropped this way, put its reason on the cart row, `evidence: {"guest_option": true, "checkout_entry": {"page_id": ..., "reason": "navigation_error"}}`, so the report can say why the cart decided. No contract change.

## 4. Nagging identity (`overlay_key` = kind + 60 masked chars; `gone None` is no close) — KEEP

DPR must never fire on what we could not prove, and a key that is too loose (kind only) would turn two different promos into "nagging". Digits masked covers tickers and counters; personalised copy does not occur for an anonymous crawler, and A/B assignment is sticky per visitor within a session, so the false-negative case is rare and its cost is a missed 0.3-severity signal, not a false penalty. `gone None` (fresh audit failed) not counting as a close is the same conservatism. No change; write both limits in the `deception.py` docstring (already partly there) for WS6b's limits list.

## 5. Never-resend memory keyed by (page URL, normalised label) — KEEP

After an uncertain click the page is in an unknown state and observe indices are re-assigned, so the label is the only stable identity; a second control with the same label on the same page is indistinguishable from the same control re-observed. Blocking it is the only reading compatible with "never retry a browser mutation". The cost (an overlay left open, reason `uncertain_earlier`) is visible in the probe and bounded to that page.

## 6. "At most one click" on a small `auto` bar — CONFIRM for unsent clicks, TIGHTEN for uncertain ones

The X may follow a first-layer reject only when nothing reached the page: reason starting with `UNSENT` (`not_executed:`, `not_observed`, `control_not_found`) or `guard_refused:`. When the reject's reason is `failed:*` or `uncertain_earlier` (the click may have been delivered) and the banner is **not interrupting and not blocking**, the chain ends there: `choice: none`, `reason` from `failed`, no X. Reason: on a bar that does not impede the funnel the alternative to a second mutation is free (leave it), and a late-firing reject plus an X is exactly the double mutation ruling 1 forbids. For interrupting or blocking banners the chain continues as today (manage, X, accept-if-blocking): clearing the way is worth the risk and `click()` re-observes first. `clicks` keeps counting executed clicks only. Pin: small bar, reject `failed:TimeoutError` -> no close click sent, `failed == ["reject:failed:TimeoutError"]`; small bar, reject `not_executed:` -> X tried.

## 7. Out-of-stock first product — ADOPT: skip unavailable candidates, keep one as fallback

A shopper who reads "Esaurito" picks another product; measuring the shop on its first sold-out item is a false negative on honest catalogues (FAI.PDP_CTA_ABOVE_FOLD False with `all`, cart/checkout and the cart DPR tests lost). Rules:
